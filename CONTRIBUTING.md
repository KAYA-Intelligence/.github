# Katkı Rehberi

KAYA Intelligence'ta katkı yalnızca kod yazmak değildir. Research, mimari,
geliştirme, test, deployment, dokümantasyon, proje yönetimi ve iletişim de
katkıdır.

## Çalışma akışı

1. Çalışmanın amacını bir issue veya kısa proje notu ile netleştirin.
2. Çalışmayı Foundation, Experiment, Project veya Product seviyelerinden biri
   olarak sınıflandırın.
3. Değişikliği ayrı bir branch üzerinde geliştirin.
4. Açıklayıcı ve küçük commit'ler oluşturun.
5. Pull request açın ve ilgili kontrolleri tamamlayın.
6. En az bir ekip üyesinden yapıcı code review alın.
7. Geri bildirimleri yanıtlayıp değişikliği doğruladıktan sonra merge edin.

Küçük öğrenme çalışmaları için issue veya pull request süreci gerektiği kadar
hafif tutulabilir. Seçilen süreç, çalışmanın seviyesine uygun olmalıdır.

## Pull request beklentileri

Pull request açarken:

- Problemi ve yapılan değişikliği açıkça açıklayın.
- Çalıştırılan testleri veya neden test gerekmediğini belirtin.
- README ve ilgili dokümantasyonu güncelleyin.
- Kurulum ve kullanım adımlarının tekrarlanabilir olduğunu doğrulayın.
- Bilinen sınırlamaları ve takip işlerini yazın.
- AI-assisted kod kullandıysanız [AI kullanım rehberindeki](./AI_USAGE.md)
  doğrulama sorumluluklarını yerine getirin.

Tamamlanmış iş için [Definition of Done](./DEFINITION_OF_DONE.md) listesini
kullanın. Liste, proje seviyesine göre ölçeklenmelidir.

## Sorumluluklar

Ekip üyeleri sabit teknik rollere ayrılmaz. Bir projede primary owner veya
reviewer olmak, kalıcı bir teknik unvan değil, o aşamaya ait sorumluluktur.
Primary owner, önemli kararları ve kazanılan bilgiyi ekip ile paylaşır.

Teknik tartışmalarda kişileri değil varsayımları, kanıtları ve sonuçları
eleştirin. Ayrıntılı davranış beklentileri için
[CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md) dosyasına bakın.
